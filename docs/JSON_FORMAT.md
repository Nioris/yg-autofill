# Формат `store-listing-*.json`

## Общие требования

Файл должен быть корректным JSON-объектом в кодировке UTF-8.

- Комментарии в JSON не поддерживаются.
- После последнего свойства нельзя ставить лишнюю запятую.
- Переносы строк внутри текста записываются как `\n`.
- Рекомендуется один файл на один язык.
- Рекомендуемое имя: `store-listing-<код-языка>.json`.

Поле `lang` внутри JSON имеет приоритет над кодом в имени файла.

## Полная структура

```json
{
  "lang": "ru",
  "title": "Название игры",
  "subtitle": "Короткое описание",
  "category": ["Казуальные", "Экономические"],
  "tags": ["тапалки", "с прокачкой"],
  "keywords": ["кликер", "машины", "завод"],
  "seo_description": "Описание для поисковых систем.",
  "about": "Полное описание игры.",
  "how_to_play": "Правила и управление."
}
```

## Поля

### `lang`

Код языка в нижнем регистре. Рекомендуется указывать всегда.

Поддерживаемые значения:

| Код | Язык в интерфейсе |
|---|---|
| `ru` | Русский |
| `en` | Английский |
| `es` | Испанский |
| `pt` | Португальский |
| `tr` | Турецкий |
| `de` | Немецкий |
| `fr` | Французский |
| `it` | Итальянский |
| `ja` | Японский |
| `ko` | Корейский |
| `zh` | Китайский |
| `ar` | Арабский |
| `hi` | Хинди |
| `id` | Индонезийский |

Неизвестный код загрузится в память панели, но при попытке заполнения язык будет отклонён как неподдерживаемый.

### `title`

Строка с названием игры. Резервный лимит — 50 символов.

```json
"title": "АвтоТАЗ Кликер"
```

### `subtitle`

Короткое описание. Резервный лимит — 70 символов.

```json
"subtitle": "30 уровней, динамические заказы и путь к суперкару"
```

Вместо `subtitle` допускается альтернативный ключ `short_description`:

```json
"short_description": "Короткое описание"
```

Если присутствуют оба ключа, используется `subtitle`.

### `seo_description`

Описание для поисковых систем. Резервный лимит — 160 символов.

```json
"seo_description": "Краткое и информативное описание игры для поиска."
```

### `about`

Основное описание игры. Резервный лимит — 1000 символов. Переносы абзацев записываются через `\n\n`.

```json
"about": "Первый абзац.\n\nВторой абзац."
```

### `how_to_play`

Описание управления и игровых правил. Резервный лимит — 1000 символов.

```json
"how_to_play": "На ПК используйте мышь.\n\n• Первый пункт.\n• Второй пункт."
```

### `category`

Одна или несколько категорий. Рекомендуемый тип — массив строк.

```json
"category": ["Казуальные", "Экономические"]
```

Допускается альтернативный ключ `categories`:

```json
"categories": ["Казуальные", "Экономические"]
```

Допускается и строка, разделённая запятыми, точками с запятой или переносами строк:

```json
"category": "Казуальные, Экономические"
```

Категория выбирается только при точном совпадении текста с видимым вариантом Яндекса. Регистр и лишние пробелы при сравнении нормализуются, но перевод, склонение и подбор похожего варианта не выполняются.

### `tags`

Массив тегов или строка со значениями через запятую, точку с запятой или перенос строки.

```json
"tags": ["тапалки", "бесконечные", "с прокачкой"]
```

Каждый тег выбирается отдельно и только по точному совпадению с вариантом Яндекса. Если, например, тег `машины` отсутствует в списке, он попадёт в итог как ошибка выбора, а остальные теги продолжат заполняться.

### `keywords`

Массив ключевых слов или готовая строка. При массиве скрипт удаляет пустые и повторяющиеся элементы, затем объединяет их через `, `.

```json
"keywords": ["автотаз", "мердж", "машины", "кликер"]
```

Эквивалентная строка:

```json
"keywords": "автотаз, мердж, машины, кликер"
```

Резервный лимит итоговой строки — 100 символов. Если объединённое значение длиннее, оно обрезается с конца и фиксируется в отчёте.

## Обязательность полей

Для полноценного заполнения каждого языка рекомендуется иметь:

- `lang`;
- `title`;
- `subtitle` или `short_description`;
- `seo_description`;
- `about`;
- `how_to_play`.

`category`/`categories`, `tags` и `keywords` нужны только при включении соответствующих флажков в панели.

Пустое локализованное текстовое поле пропускается. Скрипт не очищает соответствующее поле формы.

## Лимиты и автоматическое обрезание

Перед записью YG Autofill пытается получить фактический лимит из `maxlength` или счётчика рядом с полем. Если это невозможно, используются резервные значения:

| Поле | Резервный лимит |
|---|---:|
| Название | 50 |
| SEO-описание | 160 |
| Описание игры | 1000 |
| Короткое описание | 70 |
| Как играть | 1000 |
| Ключевые слова | 100 |

Если значение длиннее:

1. оно обрезается с конца до лимита;
2. многоточие не добавляется;
3. скрипт не оставляет половину составного Unicode-символа;
4. исходная и итоговая длина сохраняются в журнале;
5. в конце выводится раздел «ОБРЕЗАНО ПРИ ЗАПОЛНЕНИИ».

Пример:

```text
— Русский → Описание игры: 1085→1000 (срезано 85 символов)
```

Обрезание выполняется технически, а не по смысловой границе предложения. Для публикации рекомендуется после заполнения вручную проверить конец текста.

## Несколько языков

Обычно файлы лежат рядом:

```text
store-listing-ru.json
store-listing-en.json
store-listing-de.json
store-listing-tr.json
```

Можно выбрать их одновременно. Скрипт обрабатывает языки в порядке загрузки браузером.

Категории, теги и ключевые слова заполняются один раз. Источник выбирается так:

1. JSON с `lang: "ru"`;
2. если русского файла нет — первый загруженный JSON.

Поэтому эти поля можно хранить только в русском файле. Их наличие в остальных языковых файлах не требуется.

## Дубли и очистка списков

Для категорий, тегов и ключевых слов пустые значения удаляются. Повторы без учёта регистра и лишних пробелов также удаляются.

Категории и теги, уже выбранные на странице, сохраняются. Скрипт не удаляет значения, которых нет в JSON; он только добавляет отсутствующие элементы. Перед запуском очистите старые варианты вручную, если нужен точный состав.

## Имя файла

Поддерживаются любые файлы с расширением `.json`. Код языка определяется в следующем порядке:

1. `lang` внутри файла;
2. шаблон имени `store-listing-xx.json`;
3. шаблон браузерной копии `store-listing-xx (1).json`.

Если код определить нельзя, файл отмечается ошибкой и не добавляется.

## Схема

Формальная JSON Schema находится в [`../schema/store-listing.schema.json`](../schema/store-listing.schema.json). Пользовательские свойства `x-yandex-maxLength` в схеме описывают лимиты, но не запрещают более длинные строки: это соответствует поведению автоматического обрезания.
