# Как устроено заполнение

## Общая схема

YG Autofill не использует API Яндекс Игр. Он работает непосредственно с уже открытой формой в браузере и имитирует обычное изменение её элементов.

Основной поток:

```text
JSON-файлы
    ↓
определение языков и предварительная проверка
    ↓
добавление/переключение языковых вкладок
    ↓
поиск полей формы
    ↓
определение лимитов и обрезание
    ↓
нативная запись + события input/change
    ↓
точный выбор категорий и тегов
    ↓
проверка результата и итоговый лог
```

## Определение приложения

Скрипт пытается извлечь App ID из URL-путей вида:

```text
/application/568867
/app/568867
```

App ID используется для поиска старых идентификаторов полей, например `title568867`. Если ID не удалось получить, работа не останавливается: используются остальные стратегии поиска.

## Загрузка JSON

Файлы читаются через браузерный `FileReader`/`File.text()`. Содержимое хранится в памяти текущей вкладки. Собственных `fetch`, XHR или отправки файла на внешний сервер в коде нет.

Код языка определяется сначала из `data.lang`, затем из имени файла. Последний загруженный файл одного языка заменяет предыдущий.

## Поиск текстовых полей

Для каждого поля есть метаданные:

- ключ JSON;
- отображаемая подпись;
- альтернативные подписи;
- ожидаемый HTML-тег;
- старый префикс ID;
- резервный лимит;
- набор CSS-селекторов.

Порядок поиска:

1. `legacyPrefix + App ID`, например `description568867`;
2. прямые селекторы по `aria-label`, `name`, `data-testid` и префиксу `id`;
3. точный поиск видимой подписи, например «Об игре»;
4. поиск связанного элемента через `<label for="...">`;
5. поиск подходящего `input`/`textarea` внутри ближайшего контейнера;
6. геометрический поиск ближайшего элемента ниже подписи.

Невидимые, отключённые, read-only и принадлежащие панели YG Autofill элементы исключаются.

## Определение лимита

Порядок определения максимальной длины:

1. положительное значение `element.maxLength`;
2. счётчик рядом с полем вида `123/160`;
3. резервный лимит из метаданных скрипта.

Это позволяет учитывать изменения интерфейса, если Яндекс поменяет лимит в HTML, но не сам код скрипта.

## Обрезание

Строка сравнивается с лимитом по длине JavaScript-строки. При превышении берётся начало строки до лимита. Если граница пришлась между двумя частями UTF-16 surrogate pair, последняя неполная часть удаляется, чтобы не оставить повреждённый символ.

Обрезание не учитывает границы слов и предложений и не добавляет многоточие. В итог сохраняются:

- язык или контекст;
- название поля;
- исходная длина;
- итоговая длина;
- количество удалённых символов.

## Запись в React-управляемые поля

Прямое `element.value = text` иногда не замечается React-интерфейсом. Поэтому YG Autofill:

1. вызывает нативный setter `value` из прототипа `HTMLInputElement` или `HTMLTextAreaElement`;
2. отправляет событие `input`;
3. отправляет событие `change`;
4. снимает фокус;
5. ждёт обновления интерфейса;
6. сравнивает фактическое значение с ожидаемым;
7. при несоответствии повторяет попытку один раз.

Если после двух попыток значение отличается, поле попадает в `rejected`, а журнал получает `ERROR` «значение сброшено интерфейсом».

## Языковые вкладки

Для известного кода используется русское имя языка, которое отображается в консоли Яндекс Игр. Скрипт ищет существующую вкладку. При её отсутствии он находит кнопку добавления языка, открывает список и выбирает точное имя.

Если вкладки скрыты под кнопкой вида `+3`, скрипт открывает этот список и ищет нужный язык там.

## Категории и теги

Эти поля реализованы как suggested/multiselect inputs. Для каждого значения выполняется отдельный цикл:

1. найти контейнер по `data-qa` или подписи;
2. найти строку поиска;
3. проверить, не выбран ли элемент уже;
4. очистить строку и ввести значение;
5. дождаться выпадающего списка;
6. найти точное совпадение без учёта регистра и лишних пробелов;
7. отправить pointer/mouse click;
8. проверить появление выбранного chip-элемента.

Если точного совпадения нет, вариант не выбирается. В `DEBUG` по возможности выводится снимок видимых вариантов.

Существующие категории и теги не удаляются.

## Ключевые слова

Массив или строка нормализуется в список: удаляются пустые значения и дубли без учёта регистра. Затем элементы объединяются через `, ` и обрабатываются как обычное текстовое поле.

## Результаты

Каждая операция возвращает структуру со счётчиками и массивами:

```text
filled           успешно заполнено
expected         полей с данными, которые ожидалось обработать
missing          элементы страницы не найдены
missingData      для выбранной функции нет данных в JSON
truncated        успешно заполненные поля после обрезания
rejected         интерфейс сбросил значение
selectionErrors  категории/теги, которые не удалось выбрать
```

Обрезание является корректировкой, а не ошибкой. Отдельной проблемой оно становится только для ручной проверки смысла текста.

## Глобальные поля

Категории, теги и ключевые слова обрабатываются после всех языков и только один раз. Источник — русский JSON или первый файл. Это отражает структуру формы: данные являются общими, а не отдельными для каждой языковой вкладки.

## Очистка и повторный запуск

Функция очистки хранится в `window.__YGAF_CLEANUP__`. При повторной вставке скрипта старая панель удаляется. Текущий текст журнала можно получить через:

```js
window.__YGAF_LOG__()
```

Эта функция возвращает строку и удобна для диагностики из Console.
